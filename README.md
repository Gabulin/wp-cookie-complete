# Cookie Banner

Настраиваемая плашка cookies для WordPress. Актуальная единая версия: **1.0.14**. Требуется PHP 7.4 или новее.

## Установка и обновление

1. Сохраните резервную копию файлов и настроек сайта.
2. Замените `cookie-banner.php`, `banner.js` и `banner.css` в `wp-content/plugins/wp-cookie-complete/` файлами одной версии из этого репозитория.
3. Проверьте страницу в новом сеансе браузера, принятие и отказ от категорий, повторное открытие настроек и формы сайта на телефоне и компьютере.

Настройки хранятся в опции WordPress `cookie_banner_settings`. Обновление файлов не сбрасывает эту опцию. Для сохранённого шрифта Nunito также сохранена прежняя цепочка резервных шрифтов Helvetica, Arial, sans-serif. Новые параметры получают стандартные значения; сохранённые тексты, цвета, шрифты, категории, скрипты, кнопки и режим показа сохраняются. Если оформление было изменено прямо в PHP/CSS плагина, перенесите его в настройки до замены файлов.

На всех сайтах следует устанавливать один и тот же комплект файлов из одного коммита. Номер версии не гарантирует одинаковое содержимое ранее изменённых вручную файлов.

## Скрипты после согласия

В настройках категории можно указать URL внешнего скрипта, JavaScript без тегов или полный код счётчика с `<script>` и HTML-комментариями. Если заполнены URL и код, сначала загружается URL, затем выполняется код. Внешние скрипты внутри вставленного HTML выполняются последовательно с последующими встроенными скриптами. Скрипты разрешённой категории запускаются при загрузке страницы после проверки согласия.

Теги `<script>` не вкладываются друг в друга. Блок `<noscript>` и его пиксель не вставляются: загрузчик сам работает только при включённом JavaScript. При отсутствии согласия или отказе скрипты категории не запускаются. При сохранении выбора страница перезагружается.

Плагин не блокирует автоматически скрипты темы и других плагинов. Их нужно подключать через категорию, `window.cookieBanner.allows('analytics')` после события `cookie-banner-ready` либо `cookie_banner_allows('analytics')` в PHP. При серверной проверке кеш HTML должен учитывать `cookie_banner_choices`.

Редактирование исполняемого кода доступно пользователям с правом WordPress `unfiltered_html`.

## Доработки оформления

Доступны скругления дорожки переключателя и бегунка отдельно для компьютера, планшета и телефона. В ссылках текста плашки сохраняется атрибут `class`, в том числе при редактировании через TinyMCE. Стандартные цвета и включённый режим сохранены из исходной версии GitHub; индивидуальные настройки сайта имеют приоритет.

## Согласие в Contact Form 7

Текст согласия должен находиться внутри acceptance-шорткода:

```text
<p class="consent-field">
[acceptance acceptance-privacy] Я даю <a href="/consent/" class="legal-agreement">согласие на обработку персональных данных</a> и ознакомлен(а) с <a href="/privacy/" class="legal-privacy">политикой обработки персональных данных</a>. [/acceptance]
</p>
```

Если текст стоит после пустого acceptance-шорткода, CF7 выводит его вне `label`, поэтому стили темы для `.wpcf7-list-item-label` не применяются. Это исправление относится к теме/шаблону формы, а не к плашке cookies.

В `examples/contact-form-7-consent-label.php` сохранён адаптер, применённый и проверенный для такой разметки: он переносит текст в подпись чекбокса внутри `p.consent-field`. Пример **не подключается автоматически**. Предпочтительно исправить шаблон формы; адаптер можно явно подключить в своей теме, проверив её разметку. Формы с уже существующим `label` и другие блоки он оставляет без изменений.

## Проверки

```sh
npm install
npm test
php -l cookie-banner.php
php tests/options.php
php tests/contact-form-7.php
```

Браузерные проверки требуют установленный Google Chrome. Другой путь к исполняемому файлу Chromium можно передать через `CHROME_PATH`. Проверки используют локальные заглушки сетевых запросов и не отправляют данные реальным счётчикам. PHP-проверки опций используют минимальные заглушки WordPress и не заменяют проверку на самом сайте.
